## 2. Task 1.6.4 — bundled samples and first-run suggestion

**Four synthetic, offline datasets ship.** `sample_server_logs.log` (structured request events),
`sample_sales.csv` (orders by region/channel), `sample_sensors.json` (time-stamped temperature
and status readings) join the existing 600-row `sample_logs.csv` already used by the
proof-of-concept screen. `pubspec.yaml` already declares the whole `assets/samples/` directory,
so no dependency, `Cargo.lock`, Rust/FFI, generated schema or fixture file changed. The catalog
is `sampleDatasets` in `lib/engine/sample_source.dart`; each entry carries an id, title,
description, asset path, extension and format hint so the engine gets the same tie-break a
picked file would supply.

**One import path, two entry points.** `SampleSource` / `AssetSampleSource` load bytes;
`EngineSampleImporter` hands them to the real `ImportController` and adopts the engine result
into an `EngineController`; `EngineSampleLauncher` owns navigation and error reporting.
`ImportController.importBytes` gained an optional `extension` parameter for known in-memory
sources. Both seams are injected in widget tests, so no platform asset bundle, worker isolate
or native library is needed. The home screen shows the suggestion whenever the library is empty
— that includes first run — and the import screen offers the same four choices in a
`Try a bundled sample` row. Cancellations are not errors; launcher, asset and engine failures
are surfaced as snackbars, never swallowed. A successful launch reloads the library from Rust.

**Scope decision.** The suggestion is an empty-library state, not a persisted
"shown once" preference; it reappears whenever the library is genuinely empty. No
`shared_preferences`-style dependency or marker file was added for a one-line UI hint. No
golden image changed, and no device claim is made.

**Tests.** Four unit tests pin the catalog and the real import request (bytes, title, hint,
extension, timestamp, warnings and failure paths). One import-controller test covers the new
extension parameter. Two home widget tests cover the first-run suggestion and a surfaced
launch failure; two import-screen widget tests cover the sample row and its failure path.

## 3. Task 1.6.5 — empty/error/edge copy sweep

**Shared recovery copy and surfaces.** `lib/design_system/copy.dart` centralizes the sweep's
recovery wording and provides `MorphicStateMessage`, `MorphicFilterActions` and
`MorphicCommandError`. The three chart-local message widgets were replaced; existing empty
headlines remain, while a chart failure gets a human headline, the unaltered engine evidence,
and Retry. Existing import failures retain their own typed headline/next-step mapping. The
unknown/reserved-view placeholder now explains a next step when expanded.

**Explicit recovery scopes.** Empty charts and tables offer separate **Clear workspace
filters** and **Clear view filters** / **Clear search and filters** actions when applicable.
`lib/runtime/filter_recovery.dart` creates commands only for active, supported view interactions:
this matters because Rust rejects a filter command on a search-only table (and vice versa).
Clearing one scope leaves the other intact; rejected commands keep their engine evidence, retain
the current selection and offer another attempt. A workspace-filtered empty table is no longer
mislabelled as a dataset with no rows. A null metric says filters *may* affect it rather than
claiming that no rows match; when no filter can be cleared, empty views name an alternative next
step without asserting an unsupported cause. In a fixed-height table, empty/error content and
its command evidence scroll together; populated tables keep a bounded grid and scroll long
command errors separately.

**Other persistent surfaces.** Home's engine and library failures have working **Try again**
actions, without promises about storage the app cannot know. The PoC retries the failed stage
(sample profiling or workspace generation). No-workspace, no-document, no-components and
no-profile states name a next step. The field-correction sheet offers Close when no profile is
available, and directs degraded workspaces to **Restore source file** rather than suggesting a
reopen would restore missing data. Import failures already have human headlines, next steps and
raw details. Transient snackbars were not redesigned; the work does not assert that every
possible engine or platform failure has been manually reviewed.

## 4. Task 1.6.1 — design-system application sweep

**Theme and type.** Inter and JetBrains Mono are bundled with their OFL licences and pinned
source provenance (`assets/fonts/README.md`); Material icons are explicitly loaded in image
tests. Theme tokens build dark and light Material themes, with text-safe action and recovery
colours. Settings offers Dark, Light and System, remembers the choice locally, and reports a
read/write failure instead of claiming the preference was saved. Storage usage is an approximate
sum of local file lengths, not free space; failures can be retried. The limits distinguish the
64 MiB picker/clipboard ceiling from the engine's rows, columns and estimated memory budget.
The mirrored engine defaults have a source-level drift test.

**Home and workspace.** Recent entries show the indexed title, dataset hash and modification
time when available; returning from a workspace or replaced import route reloads the index.
On compact screens the missing-source notice retains its recovery action without duplicating
it in the crowded app bar, leaving room for the title-edit affordance. The notice also appears
when a degraded document has no components; if the document itself is absent, the app-bar
recovery action remains as a fallback. The live title editor issues an undoable
`RenameWorkspace` command rather than the library rename API, which would close the session
and reset its history. Rust trims and validates the title atomically, journals the change,
updates the index and preserves prior undo frames; a no-op changes neither revision nor history. This additive command raises the bridge contract
from **v13 to v14** without a new FFI function. The status line distinguishes already-persisted
edits from a pending checkpoint; a just-adopted import now schedules that checkpoint even
when its dirty notification preceded the workspace's first build.

**Real-event motion.** Import stage labels change only when the engine reports a new phase;
no percentage or artificial delay is invented. After a successful import, components share
one 400 ms clock with a 200 ms fade/4 dp rise and up to 40 ms stagger; reopening is immediate.
Reduced motion removes translation and stagger while retaining opacity. Layout-change animation
is not yet an established design-token guarantee; responsive and accessibility tasks remain.

**Scope and evidence.** The font-loaded image suite covers the four key screens in both themes,
including import failure and missing-source recovery, and adds metric/table ready, empty and
error snapshots alongside the existing bar/line/timeline snapshots. This supplies *some*
golden coverage of all five component families, not the complete AT-11 loading,
empty-after-filter and binding-error matrix. Tests cover theme persistence and failure,
selected contrast pairs, real-event motion, title history and the checkpoint/reload paths.
These are host tests, not a complete contrast audit, responsive acceptance or TalkBack pass.
