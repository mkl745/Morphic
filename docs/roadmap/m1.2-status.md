## What 1.2.1 actually delivers

A new `morphic-ingest::json` module: `parse_json` / `parse_json_with`, sharing `IngestOptions`,
`CancelToken`, `Progress` and `ImportReport` with the CSV path.

**Scope decision — this is the parser, not a user-visible feature.** `morphic-core` and the
bridge still call CSV only, and the import screen still says *"JSON and structured logs are
not supported yet."* Auto-detection and the `formatHint` UI are task 1.2.3, and the import UX
is 1.2.4. Wiring JSON into the app before sniffing exists would mean a second hard-coded
entry point to rip out again. **Nothing a user can see changes in 1.2.1**, and this document
does not claim otherwise.

### Shapes

| Input | Result |
|---|---|
| `[{…}, {…}]` | one row per element |
| `{…}` | one row |
| `[1, 2, 3]` | a single `value` column, reported |
| top-level scalar | one row, `value` column |
| element that is itself an array | quarantined, not guessed at |
| `{"data":[…],"meta":{…}}` | one row + a warning naming the record-array fields |

The wrapper case is deliberate: silently picking one of several arrays would be wrong often
enough to be harmful. Extracting a wrapper belongs to 1.2.4's re-import-with-hint flow.

### Bounded memory

The document is **not** materialised as a `serde_json::Value` tree when the top level is an
array — that costs roughly 5–10× the file size and would defeat the 256 MiB gate on a 4 GB
phone. A forward-only scanner tracks string state, escapes and nesting depth, and yields one
element slice at a time, so peak parse memory is the largest *element*, not the file.

Two new gates, both returning the new `IngestError::ResourceLimit` with actionable copy:

- `max_import_bytes` — **256 MiB**, checked before any parsing work.
- `max_memory_bytes` — **512 MiB**, checked per row against retained cell bytes.

`max_rows` / `max_columns` are reused; the column cap applies to the **union** of keys across
all records, not to any single record.

### Flattening

Dotted paths to **depth 4**. Nothing is dropped: a subtree deeper than the cap, and any array
value, is retained as **compact JSON text** in that column, with one warning per affected
column (not per row). `{}` and `[]` are kept so a field's existence survives. Keys that
collide after flattening (`{"a.b":1}` vs `{"a":{"b":2}}`) get a numeric suffix and a warning.

### Typing and nulls

Scalars are rendered to text and passed through the **same** `column::build_column` ladder as
CSV, so the formats cannot drift apart on types and ISO-8601 strings from APIs become real
timestamps.

Nulls come from JSON `null` or an absent key **only**. The CSV null-token vocabulary is
deliberately not applied — `"null"`, `"N/A"` and `""` are real string data in JSON, and
applying CSV's vocabulary would silently destroy them. Absent keys are back-filled as null in
both directions as the column union grows.

### Robustness

- A malformed element does not discard the rows already read; it is quarantined and counted.
- More than `max(1% of rows, 1000)` unreadable elements fails the import with diagnostics
  (architecture/05 §1.3) rather than importing nonsense.
- A trailing comma is accepted **and reported**; content after the closing `]` is ignored
  **and reported**. A leading/doubled comma or an unclosed array is a typed error.
- Cancellation and the `Sniffing → Parsing → Typing → Done` progress contract match CSV.

## What 1.2.2 actually delivers

Three new parsers — `jsonl`, `text`, `log` — plus a `records` module extracted from the JSON
parser so the JSON-shaped formats share one flattening/null/naming/typing/quarantine policy
instead of two copies that drift. A test asserts JSON and JSONL produce identical columns,
types and null masks for identical records.

**Still parser-only.** Core and the bridge continue to call CSV; auto-detection is 1.2.3.
Nothing a user can see changes in 1.2.2 either.

### JSONL

Streaming line-at-a-time. Blank lines skipped, trailing newline is not a row, CRLF handled.
A bad line is quarantined without ending the parse and the **first 20 line numbers** are
reported (architecture/05 §1.3).

### TXT

`line_number` + verbatim `line`. **Blank lines are kept** and reported — dropping them would
misalign every line number against the source. Text is never trimmed. Both columns still go
through the shared type ladder.

### LOG — pattern library v1

`regex` was already locked and is the crate dependency-strategy §3 names for this job, so no
new supply-chain surface. Patterns are compiled once via `OnceLock`.

The pattern is chosen **once** from up to 256 sampled lines, then applied to every line — a
file cannot end up half-parsed one way and half another. Selection evidence (pattern, match
count, rate) is always reported; below the documented 70% bar a low-confidence warning is
added.

| Pattern | Core columns |
|---|---|
| `iso-level` | time, level, service, message |
| `syslog` | time, level, host, service, pid, message |
| `common-log` | time, host, ident, authuser, message, status, bytes, referer, user_agent |
| `logfmt` | time, level, service, message (from aliases) |
| `fallback` | time, level, message |

Core columns are always emitted (null when absent) so column order never depends on which
line carried a field first. `key=value` pairs are promoted to columns, capped at **64**
distinct keys with the cap reported; a tail key can never overwrite a field the structured
prefix already extracted. Levels canonicalise for grouping, syslog `PRI` decodes to a
severity, and CLF `-` becomes null. **Unmatched lines keep their entire raw text in
`message`** — a log import never fails and never drops a line for looking odd.

## Limitations and debt introduced or found by 1.2.1

- **JSON column order within a record is sorted, not file order.** `serde_json`'s default
  `Map` is a `BTreeMap`, so `{"date":…,"open":…,"close":…}` yields `close, date, open`. It is
  deterministic and pinned by a test, but it is not what the file said. Preserving source
  order needs a local order-tracking deserializer (1.2.4): enabling
  `serde_json/preserve_order` workspace-wide would reorder every serialized document and
  break the schema and compiler goldens.
- **CSV and JSON now differ on the quarantine ceiling.** JSON enforces `max(1%, 1000)`; CSV
  still only warns and stops after 100 consecutive failures. Aligning them is 1.2.3 work.
  Recorded here rather than left as a silent behavioural difference between formats.
- Array elements that are themselves arrays are quarantined rather than flattened into
  positional columns. No corpus evidence yet says that is the right call; revisit in 1.2.4.
- A single top-level object is still parsed whole. The byte gate bounds it, but a 200 MiB
  single object will spike memory in a way a 200 MiB array will not.
- Ingestion remains whole-file in memory for the decode step (inherited M1.1 debt); the JSON
  scanner removes the *parse-tree* multiplier, not the decoded `String`.
- `chardetng` statistical charset detection is still outstanding (1.2.3).

## Limitations and debt introduced by 1.2.2

- **Log service detection is a heuristic.** `[svc]` is unambiguous; a bare token is taken as
  a service only when it starts lowercase. `INFO Request received` keeps the phrase as the
  message, but `INFO request received` reads `request` as a service. Disclosed on every
  iso-level import rather than hidden.
- **syslog and CLF timestamps stay text.** RFC3164 has no year; CLF uses month names. The
  temporal ladder refuses both rather than guessing, and a warning says so. Promoting them
  depends on the locale/year inference M1.1 deliberately deferred.
- The pattern library is **v1**: no multiline/stack-trace folding, no JSON-in-log detection,
  no Apache error-log or klog pattern. These are extraction gaps, not data loss — unmatched
  lines survive verbatim.
- TXT and log parsing still decode the whole file to a `String` first (inherited M1.1 debt).
  The per-line parse is streaming; the decode is not.

## 1.2.3 — Format sniffing consolidation, override UI, encoding edges

**Status: DONE — CI-verified.** Run **42234638594**, commit **`ac08894`**, all 6 jobs green.
**482 Rust tests** (+65) and **130 Dart tests** (+7); `PERMISSIONS_OK`,
`RUNTIME_OK: range 1-256 of 600`, `PAGING_OK`. Exit criterion from the plan: *malformed corpus
green* — met, and met by making the corpus import correctly rather than by loosening a test.

### Delivered

- **`morphic-ingest::detect`** — one content-first detector for all five formats. Probes the
  first 64 KB (cut at a newline), samples ≤ 256 lines, and returns the format, a confidence,
  the evidence string and any caveats. `ingest()` / `ingest_with()` dispatch on it, so
  `morphic-core` and the bridge are no longer CSV-only.
- **Two thresholds per probe, not one.** ≥ 50% agreement *chooses* CSV or LOG; ≥ 90% / ≥ 70%
  makes it *confident*. This is what implements the documented "ambiguity resolves to the
  richer interpretation" rule: `malformed/ragged.csv` (field counts 3,2,4,3) stays CSV at 0.50
  confidence with a raggedness warning instead of collapsing to TXT, and `malformed/mixed.log`
  (3 of 5 lines) stays LOG at 0.60 with the unmatched lines kept verbatim. Modelling the
  detector against the corpus caught both of these before the first CI round.
- **`formatHint` override, end to end.** Rust `IngestOptions.format_hint` → `CoreError::
  UnknownFormat` for a bad hint (never a silent fall back) → `morphic_import` on the bridge
  (API version 2 → 3) → `MorphicBridge.importFile` → `ImportRequest` → a **Format** dropdown
  on the import screen defaulting to *Detect automatically*.
- **Extension is the weakest evidence.** It decides only when no content probe was decisive
  (including an empty file) and says so; when it disagrees with the contents, the contents
  win and the disagreement is reported. The picker now offers csv/tsv/txt/json/jsonl/ndjson/log.
- **`open_session` reopens with detection.** It previously forced `parse_csv`, which would
  have corrupted every saved JSON/JSONL/log/txt workspace on reopen. A bridge test pins a
  JSON workspace surviving close → reopen.
- **Encoding edges.** Invalid/mixed UTF-8 now reports the count of bad sequences and the
  byte offset of the first; mixed CRLF/LF is reported; lone CR is called out explicitly
  (neither `str::lines` nor the `csv` crate splits on it, so a CR-only file would otherwise
  become one giant row); probable UTF-16/32 without a BOM is flagged rather than guessed.
- **The headline warning is always first**: `Read as '<fmt>' (<n>% confidence): <evidence>.`

### Limitations and debt

- **`chardetng` is still deferred, now with a concrete reason.** It is absent from
  `Cargo.lock` and this environment cannot reach crates.io to compute the checksums a locked
  dependency needs. Latin-1 remains the total, never-panicking substitute; the residual gap
  is windows-1252 punctuation in 0x80–0x9F, and the warning now quantifies the damage.
- **CSV still lacks JSON's quarantine ceiling** (`max(1% of rows, 1000)`). Carried forward
  from 1.2.1/1.2.2 rather than silently closed here; it is a parser-policy change, not a
  detection change, and belongs with the 1.2.4 import-UX work.
- **Detection reads a 64 KB window, so a file that changes format partway through is
  classified by its head.** A CSV with a JSON appendix imports as CSV. Disclosed as a design
  limit, not a bug: the alternative is scanning the whole file, which the memory budget forbids.
- **No per-format preview yet.** The user sees the evidence line after importing, not before.
  That preview, and re-importing in place, is 1.2.4.
- The 10 MB → ≤ 3 s import target and the mid-class device gate remain **unmeasured**; 1.2.3
  adds no device evidence.

### CI rounds

Two rounds, and the first one was behaviourally clean — every new Rust bridge test (8) and
every new Dart test (7) passed on the first run that compiled, including the JSON
close→reopen regression guard.

1. **42234136961 ❌** — three mechanical issues, no behavioural ones:
   - `clippy::useless_format`: `vec![format!("…")]` with no interpolation is just a `String`.
   - `morphic-bridge::engine_info_returns_json` still asserted `apiVersion == 2` after the
     bump to 3. The Dart fakes were updated but this Rust assertion was missed.
   - **A UI copy collision.** The new footer said "any rows it *could not* parse", and the
     cancel-is-not-an-error test asserts `find.textContaining('could not')` finds nothing in
     order to prove no error card appeared. Explanatory prose impersonated a failure.
     Reworded to "was unable to". Worth remembering: on this screen, error-state tests match

2. **42234638594 ✅** — all six jobs green.

## 1.2.4 — Import UX: facts, quarantine report, re-import, cancel, human errors

**Status: DONE — CI-verified.** Run **42248008908**, commit **`a6dd398`**, all 6 jobs green.
**491 Rust tests** (+9) and **167 Dart tests** (+37); `PERMISSIONS_OK`,
`RUNTIME_OK: range 1-256 of 600`, `PAGING_OK`.

### Delivered

- **Cancellation, end to end.** `morphic_cancel_import(workspace_id)` on the bridge →
  `MorphicBridge.cancelImport` → `ImportController.cancel()` → a **Cancel import** button.
  The token registry uses a **separate lock** from the engine registry: `with_engine` holds
  the engine lock for the whole import, so a cancel call that needed it would block until the
  import it was trying to stop had already finished. Registration is RAII, so the id is
  removed on success, on error and on a panic through the firewall.
- **A cancelled import provably writes nothing (AT-05).** Core's `import` was reordered so
  the dataset id is computed from `content_hash` *without writing*, the document is compiled
  and validated, and only then — after a final cancellation checkpoint — are the dataset and
  workspace written. Tests cover pre-cancelled, cancelled from inside a real progress event,
  and a cancelled re-import of an existing workspace. A bridge test drives the whole path
  through the C ABI and asserts the store is empty afterwards.
  - This also fixes a pre-existing bug: a **validation failure used to orphan a dataset**,
    because `put_dataset` ran before `validate_with_profile`.
- **Cancellation is a state, not an error.** `ImportStage.cancelled` renders a neutral card
  ("Nothing was saved"), never the red error card. This matches the contract's `Cancelled`
  row, which specifies a silent surface.
- **File facts card.** Format, encoding, rows, fields, rows set aside (with the percentage)
  and the engine's confidence — all read from `ImportReport`, none re-derived in Dart.
- **Quarantine / import report sheet.** The detection headline, the quarantine arithmetic,
  every caveat, the engine's raw error when there was one, and chips to re-read the file as
  another format.
- **Review before trust.** A clean, confident import still navigates straight to the
  workspace — the spec asks for no ceremony when nothing is wrong. An import with
  quarantined rows or confidence below 90% stays on the import screen with a *Worth a look
  first* card offering **View report** or **Open anyway**.
- **Re-import with a hint** from the report sheet, reusing the bytes already in hand (no
  second file read). It creates a **new** workspace and leaves the earlier attempt alone
  rather than silently overwriting it.
- **Human error copy** (`import_failure.dart`). The byte gate and the memory gate are
  different problems and get different advice; so do the column ceiling, the row ceiling,
  malformed content, an unknown hint, and a storage failure. Every failure carries a
  headline, a next step, and the engine's original text — the raw message stays visible
  because it is the evidence a bug report needs.

### Notes and limits

- **Bridge API version 3 → 4** for the additive `morphic_cancel_import` symbol.
- Error classification matches the stable prefixes of the Rust `Display` strings rather
  than a new error-code field, so the FFI error shape is unchanged. The Dart tests use the
  engine's real strings, so a wording change shows up as a classification failure.
- **Cancel is only offered during the engine call.** The read-from-disk stage is local and
  fast; there is no honest way to interrupt `readAsBytes`, so the button does not pretend to.
- `cancel()` returning false is a normal answer, not a failure: the import may have finished
  between the tap and the call. Its result then stands.
- The report sheet lists caveats but **cannot yet show the quarantined rows themselves** —
  the engine reports counts and reasons, not the offending records. Surfacing the rows needs
  a quarantine store and is not in this task.

### CI rounds

Three rounds. The first two failures were instructive rather than random:

1. **42247088022 ❌**
   - **Two cancellation errors with the same message.** The parser returns
     `IngestError::Cancelled`, which core wrapped as `CoreError::Ingest(..)`, while the new

2. **42247646995 ❌** — Rust green, one widget test left. `scrollUntilVisible` stops as soon as

3. **42248008908 ✅** — all six jobs green.

show everything, or `ensureVisible` before tapping. A finder matching is not evidence that a
widget can be tapped.

## 1.2.5 — ◇ Clipboard import; ◇ share-to-Morphic evaluation

**Status: DONE — CI-verified.** Run **42256267974**, commit **`fccec5c`**, all 6 jobs success.
Totals: **491 Rust** tests (unchanged — this task is Dart-only) and **188 Dart** tests
(167 → 188, +21). Gates: `PERMISSIONS_OK`, `ENGINE_FFI_OK`, `POC_OK`,
`RUNTIME_OK: range 1-256 of 600`, `PAGING_OK`.

Both items are marked ◇ stretch in the plan, and the second is scoped as an *evaluation*,
which is what was delivered.

### Delivered

- **Clipboard import, end to end.** `PlatformClipboardSource` → `SystemClipboardSource`
  (Flutter's built-in `Clipboard`, **no plugin and no permission**) →
  `ImportController.importClipboard` → a **Paste from clipboard** button. Pasted text goes
  through the same detector, facts card, report sheet, cancel and re-import path as a file.
- **No extension is offered for a paste.** A clipboard has no file name, so the contents
  decide the format — which is the detector's job and what it is good at.
- **No invented reading stage.** The bytes are already in hand, so the controller does not
  claim to be reading anything.
- **The ceiling counts UTF-8 bytes, not characters.** A CJK or emoji payload is several bytes
  per character and the engine's budget is in bytes; a 40-character accent-heavy string is
  80 bytes and is refused by a 64-byte cap. Tested.
- **An empty or whitespace-only clipboard is an ordinary outcome**, reported plainly rather
  than as "the file is empty", which would be a confusing thing to learn after a paste.
- **Honest platform copy.** Android 13+ shows its own system notice when an app reads the
  clipboard; the screen says so, so it does not look like an unexpected Morphic prompt.
- **[ADR-0015](../decisions/ADR-0015-share-to-morphic.md) — the share evaluation.** Three
  findings: `share_handler` is disqualified on **AGP 9 / Built-in Kotlin** (the same failure
  that killed `file_picker` 11.x); the maintained fork `better_share_handler` supports it;
  and the Android manifest is **generated in CI, not committed**, so intent filters need a
  new manifest-patching build step. Share stays in M1.6 as the dependency policy already
  placed it, with a six-step implementation plan recorded so the deferral is actionable.

### Notes and limits

- **Clipboard reads require focus.** Android 10+ only lets the foreground app read the
  clipboard, so the read happens on a user tap. There is no background clipboard access.
- **Share-to-Morphic is not implemented.** Users can paste text but cannot yet share a `.csv`
  from Files into Morphic. This is the documented consequence of ADR-0015, not an oversight.
- The screen tests now run on a deliberately tall surface. 1.2.4 learned that
  `scrollUntilVisible` stops at "found", and a `ListView`'s cache extent means found is not
  hit-testable; these tests assert content and behaviour, not layout.

### CI rounds: 3

| Round | Commit | Verdict | Cause |
|---|---|---|---|
| 1 | `f4297db` | Dart analyze + test ❌ | 10 issues, 4 root causes (below) |
| 2 | `7752f42` | analyze ✅, test ❌ | preview truncation was 58 chars against a 60-char budget |
| 3 | `fccec5c` | **all 6 ✅** | — |

**What round 1 taught.** Five of the ten analyzer issues came from *one* mistake: a Python
insertion anchored on a `}` put the new `group(...)` inside `ThrowingCancelBridge` instead of
inside `main()`, so the parser read a test registration as a method declaration. Brace-balance
checking passed because the braces *were* balanced — balance is not scope. The lesson for
future scripted edits: anchor on a **named** landmark (the group title that precedes it, the
doc comment of the following declaration), never on a bare closing brace.

The second cause was a Dart rule worth remembering: **promotion of a local that is assigned
after its declaration does not survive into a closure.** `if (content == null) return;` proving
non-null in the function body says nothing inside `setState(() { ... })`. Take a non-nullable
copy first.

**What round 2 taught.** The failing assertion was right and the implementation was wrong: the
preview kept 57 characters and appended an ellipsis, producing 58 against a documented budget of
60. Two magic numbers that must agree had drifted. The fix names the limit and derives the cut
from it. When a test and its implementation disagree, decide which one is the contract before
editing either — here the contract was written down, and it was the code that had wandered.

## AT-02 — schema detection accuracy, now measured

**Status: DONE — CI-verified.** The standing report listed this as a gap no task row owned:
the claim existed, the labels did not, and nothing scored it. It is now a gate.

### What was built

- **`fixtures/expected/schema-labels.json`** — ground truth for **21 files / 90 fields**,
  authored from the file contents and never from the profiler's output. Rules are written down
  (dtype is what the bytes justify; role is what the field means) and debatable calls carry a
  note. Two fixtures added to reach the corpus floor: `sales.csv` (the product-shaped case)
  and `sensors.json`.

### The measurement, and what it changed

| Round | dtype | role | What it revealed |
|---|---|---|---|
| 1 | 98.9% | **72.2%** | 25 misses in six clusters — 13 points below the 85% bar |
| 2 | 100% | 98.9% | one CLF offset bug; two core tests pinned the old behaviour |
| 3 | **100%** | **100%** | — |

The six causes were all in the role heuristic: booleans returned `Unknown`; the near-unique
rule ran first so unique **prose** became a key (log messages, notes, TXT lines); uniqueness
alone was treated as proof of identity, so five latencies in five rows looked like five ids;
nothing recognised an identifier by name; `looks_temporal` only knew ISO, so CLF, RFC3164 and
unresolved slash dates lost their temporal role; and numeric codes were measures, which makes
a mean HTTP status meaningful. All six are fixed, with 12 unit tests pinning the rules and the
traps they introduce (`"May we help you?"` must not become temporal; `line_number` must not be
mistaken for a payload).

**One label was wrong, not the engine:** `access.log`'s RFC1413 `ident` is `-` on every line, so
`null` / `unknown` is the honest answer. The scorecard caught a labelling error on its first
run, which is the loop working.

**Four compiler goldens changed and every change is an improvement:** a bar chart of record
counts over unique prose is gone; `Avg qty` appeared; an unresolved date column now yields a
trend instead of a bar chart of date strings. Reviewed before accepting.

### Honest limits

- **100% on a corpus the rules were tuned against is an upper bound, not a generalisation
  estimate.** The caveat is printed inside the scorecard itself so the number cannot travel
  without it. Turning it into an estimate needs held-out files scored *before* any rule change.
- 21 files is the spec's floor, not a representative sample. Real exports, other locales and
  unfamiliar column names are not in it yet.
- **For M1.4:** a `line_chart` can now be bound to a **text** temporal field (the compiler has
  always preferred typed timestamps but permits text roles). The time-bucketing aggregation
  path must either parse those values or refuse with an explanation — it must not silently
  bucket strings.

### CI improvements this forced

- `cargo test --workspace --no-fail-fast`: a golden failure was cancelling morphic-core's tests,
  so the scorecard said "not produced" exactly when it was most needed.
- The report extracts failing test names and panic messages, not just the last 80 lines.
- A commit message containing `[regenerate-goldens]` regenerates snapshots and the bot pushes
  the diff. There is no local Rust toolchain here, so the alternatives were hand-editing

## Fuzz smoke — the exit's crash-safety clause

**Status: DONE — CI-verified.** Run **42273176017**, commit **`b9269be`**, all 6 jobs success;
**511 Rust** tests, 188 Dart. M1.2's exit says "malformed corpus never crashes (fuzz smoke
clean)". What existed was five fixtures passed to `ingest()` with the result discarded, plus
per-parser random-byte sweeps. Neither checked an invariant, bounded the time, or fuzzed
**detection** — and a misdetection is the more likely bug.

### What runs now

`engine/crates/morphic-ingest/tests/fuzz_smoke.rs`, on **every CI push**: 3,000 cases mutated
from 35 seed files (the whole valid + malformed corpus plus nine synthetic shapes), through the
public `ingest_with` entry point so format detection is exercised too. Ten operators: truncate,
flip bytes, inject hostile tokens (NUL, invalid UTF-8, lone surrogates, mid-stream BOM, `NaN`,
`1e999`, impossible dates, ANSI escapes, quote and comma floods), delete and duplicate slices,
splice two seeds, wrap to force a different format, substitute delimiters, repeat, newline
chaos. splitmix64 makes the stream identical on every platform, so a reported seed reproduces a
failure exactly.

### First measured run

| | |
|---|---|
| cases | 3,000 from 35 seeds |
| accepted as a table | **2,175** |
| refused with a typed error | **825** (696 json, 129 empty) |
| formats detected | all five — csv 1112, log 432, txt 363, json 242, jsonl 26 |
| largest input | 18,588 bytes |
| total time | **892 ms**; slowest case **16 ms** (budget 10 s) |
| panics / invariant failures | **0** |

### What it asserts beyond "did not panic"

- Every outcome is a `Table` or a typed `IngestError` **with a non-empty message**.
- The report agrees with the table it describes (rows and fields), and every column buffer
  matches the row count. Silent corruption is worse than a crash: the user sees numbers that
  came from nowhere.
- No case exceeds a 10-second budget — a cheap guard against catastrophic regex backtracking,
  the realistic denial-of-service in a log parser.
- Identical bytes reparse to identical names, rows, format and warnings, because reopen depends
  on it.
- A pre-cancelled token is honoured on adversarial input (200 mutated cases).
- **The stream itself must stay interesting**: no tables, no refusals, or only one detected
  format fails the test, so a smoke that quietly stopped testing cannot stay green.

Plus named structural attacks: 3,000 columns, a lowered row cap, a lowered byte gate, 400-deep
JSON, and a half-megabyte single line.

### Honest limits

- **Seeded mutation, not coverage-guided fuzzing.** cargo-fuzz is deliberately not adopted: it
  needs a nightly toolchain and a maintained corpus, neither verifiable in this build
  environment. Deferred to M1.7's reliability week.
- Only `empty` and `json` errors appeared in 3,000 cases. The resource gates are covered by the
  named attacks with lowered limits, not by the random stream — the report says so rather than
  implying the stream reached them.
- **The nightly workflow has never executed.** GitHub only registers workflow files from the
  default branch; `nightly.yml` lives here, so `gh workflow run nightly.yml` returns 404 and the
  cron has never fired. The deep 40,000-case run is wired there and will start when this branch
  merges to `main`. That is also why `cargo-deny` and `cargo-audit` have still never run.
