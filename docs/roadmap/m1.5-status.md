## 4. Task 1.5.3 — library lifecycle and hash-verified re-link

`e12c82c` added four additive FFI entry points and the engine operations behind them:
`morphic_rename_workspace`, `morphic_duplicate_workspace`, `morphic_delete_workspace` and
`morphic_relink_workspace`. `API_VERSION` went 9 → **10**; no existing entry point changed shape.
Rust owns the document, library index and undo seed:

- **Rename** trims and rejects an empty title, bumps `revision`, rewrites `modifiedAt`, re-seeds
  `history.json` and drops the open session so the next snapshot reads the new title from disk.
- **Duplicate** refuses an existing id, writes a second document with a fresh id, timestamps and
  `revision = 1`, plus its own empty journal/history. It **shares** the content-addressed dataset —
  no source bytes are copied.
- **Delete** removes the workspace folder and library entry but deliberately keeps the dataset,
  because another workspace may reference the same hash.
- **Re-link** refuses bytes whose SHA-256 does not equal the `datasetId` already in the document;
  on a match it re-adds the immutable source and drops the session so the table, profile and
  metrics rehydrate on the next open.

Flutter's home library gained a per-row menu (Rename / Duplicate / Delete / Re-link source file),
a rename dialog, a delete confirmation, and a visible snackbar for both success and engine
rejection. A cancelled dialog or file pick makes **no** bridge call. Degraded workspaces now have
two recovery affordances: a link button in the app bar and a **Restore source file** button inside
the notice itself. Both go through the same hash-verified bridge call. The three fake bridges were
extended, and the file picker is injectable so widget tests need no plugin or native library.

## 5. Task 1.5.5 — field corrections UI and targeted recompilation

`dc8a38f` shipped the correction flow; `23513e0` is the CI-green tip. `API_VERSION` went 10 →
**11**, adding one additive command, `ClearFieldOverride { field }`, through the existing
`morphic_apply_commands` array — no FFI entry point changed shape.

**Engine.** `morphic_schema::Binding::fields()` names every dataset column a binding reads.
`morphic_compiler::recompile::effective_profile` applies the persisted `fieldOverrides` to the
inferred `DatasetProfile`, and `recompile_for_fields` calls the real `compile` **once** with that
corrected view. Only components whose binding reads a corrected field are considered. Where the
corrected profile still generates that component, its fresh binding and explanation are copied;
where it no longer does, the binding is repaired in place (an average over a now-text field
becomes a row count) rather than dropping the component or inventing a new layout. Layout order,
hints, titles, converted types, interaction state and the override records themselves are never
rewritten; components that read no corrected field are byte-identical. `affected` names only the
recompiled plus directly touched components. A prior correction may have removed the field from a
binding, so clearing a correction also consults the *freshly compiled* binding — otherwise the
original average could never come back.

Overrides deliberately do **not** re-parse the imported bytes: the query layer keeps the dtype it
ingested, while the planner and `validate_bindings` use the corrected view. The rebuilt components
are probed against the effective profile before any write; a correction that would leave an
uncomputable binding is rejected. In degraded mode there is no live profile, so the correction is
persisted but not recompiled, and every component is reported affected rather than pretending the
recompile was targeted. Contract doc 02 §2.4.5 and persistence doc 06 §7 were updated in the same commit; the
generated UI schema artifact is unchanged, so drift stayed ✅.

**Flutter.** A long press on a `data_table` header opens `field_corrections.dart`, which reads the
inferred and effective values from Rust, shows the closed dtype/role vocabularies, emits the three
commands, and shows a small badge on corrected columns. The scripted bridge now persists
`fieldOverrides` and handling for all three commands; the interaction drift gate covers ten tags;
the three `EngineInfo` fakes and the FFI `engine_info` test were bumped to v11.

**Tests (AT-17).** Three Rust core tests cover targeted recompilation with a byte-identical
record-count card, persistence across `close_session` + `load_workspace`, undo restoring the
semantic `state_hash`, and clearing an override restoring the inferred average. Four compiler
tests cover `effective_profile`, targeted scope, an empty change set being a no-op and a repaired
binding validating against the corrected profile; one schema test pins `Binding::fields` for all
five bindings. Four Dart widget tests drive the real long-press → sheet → command → badge → reset
flow. AT-17's automated criteria are now **green**: only affected components recompile, the
override persists, and undo restores the original inference. It makes **no device claim**.

## 8. Task 1.5.6 — `.morphic` bundle export/import

`ee57c55` shipped the stretch row; `a8e42e4` is the CI-green tip after the red first run and the
rustfmt bot push `61817a2`. `API_VERSION` went **12 → 13** (contract doc 02 §2.4.7). Two additive
FFI entry points joined the bridge: `morphic_export_bundle(root, id, now)` returns
`{bundleJson, bytes, manifest}`, and `morphic_import_bundle(bytes, len, root, newId, title, now)`
returns the imported document, source title and verified dataset count. No existing entry point
changed shape and no Cargo dependency or `Cargo.lock` line was added.

**Format.** The Phase 0 ZIP sketch in doc 06 §1/§4 is *not* what shipped. A `.morphic` file is a
single UTF-8 JSON envelope: a camelCase `BundleManifest` (`format`, `schemaVersion`,
`workspaceId`, `title`, `exportedAt`, `datasetCount`), the authoritative `WorkspaceDoc`, and every
referenced source as lowercase hex in `datasets[]` with `hash`, `sourceName`, `contentHex` and
`bytes`. `decode_bundle` verifies the manifest format, workspace/schema identity, declared dataset
count, every byte count and every SHA-256 content hash **before** a dataset or workspace is
written. Import re-seeds the document at revision 1 under a fresh id and calls `open_session`, so
a tampered envelope fails at the boundary and leaves the store untouched. Doc 06 §7 records the
deviation; a future ZIP reader is not implied.

**Flutter.** The home screen gained the `import-bundle-button` and an `Export .morphic bundle`
workspace-menu action. `PlatformFileSource.pickBundle()` reuses the injectable picker seam; a
`BundlePathResolver` selects the app-private documents directory and a separate `BundleWriter`
writes the bytes. Both are injected in widget tests, so no platform channel or real disk I/O is
needed inside `testWidgets`. Cancellations, picker errors and engine rejections are surfaced; a
successful import reloads the library from Rust rather than editing the index in Dart.

kill-mid-save chaos suite (3 + 1 + 1 cases), Dart analyze/test/goldens, Schema artifacts drift,

gate cases. `STAMP_OK` shows `a8e42e4` in the APK, `PERMISSIONS_OK`, and the main manifest still
