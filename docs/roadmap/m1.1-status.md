## What 1.1.1 actually delivers

`morphic-ingest` was rewritten from the Phase 0 PoC parser into a production CSV path:

- delimiter sniffing by *consistency* (`, ; TAB |`), header sniffing, both overridable and
  both reported;
- BOM-aware strict UTF-8 with a reported Latin-1 fallback, plus UTF-16 BOM support;
- the **95% type ladder** (`bool → int64 → float64 → utf8`) with per-column coercion counts —
  a single `N/A` no longer collapses a numeric column to text;
- configurable null tokens, ragged-row repair, quarantine accounting with an anti-spin guard;
- `CancelToken` cooperative cancellation and real `Progress` events
  (`Sniffing → Parsing → Typing → Done`);
- typed `max_rows` / `max_columns` memory gates.

Contract and debt: [crate README](../../engine/crates/morphic-ingest/README.md).
New fixtures: `semicolon.csv`, `tab.tsv`, `headerless.csv`, `tolerant_types.csv`, `latin1.csv`.

**Test growth (measured):** `morphic-ingest` went from **8 → 55** tests
(`lib.rs` 29, `sniff.rs` 11, `column.rs` 10, `decode.rs` 5); the Rust workspace went from
**34 → 81** tests, all passing. Two real defects in the hand-written code were caught by the
strict gates and fixed: rustfmt drift (auto-formatted) and clippy `byte_char_slices` on the
delimiter table.

**Runtime evidence (emulator, not a device):** run 42087083874 reports `ENGINE_FFI_OK` and
`POC_OK` (CSV profiled by Rust, 12 rows rendered). This does **not** satisfy the device rule.

## What 1.1.2 adds

**Normalized timestamps.** New `DataType::Timestamp` + `ColumnValues::Timestamp(Vec<i64>)`
holding **UTC milliseconds**. `morphic-model::temporal` carries the pure civil-date math
(Hinnant algorithms, round-trip tested every day from 1800–2200) so ingest and the profiler
share it with **no `chrono` dependency and no timezone database**.

The ladder is now `bool → int64 → float64 → timestamp → utf8`. Three deliberate refusals,
each reported rather than guessed:

1. **Ambiguous day/month** (`01/02/2024`) stays text unless some row has a component > 12;
   a self-contradictory column is also refused.
2. **Bare integers** (`20240115`, epoch-looking numbers) stay `int64` — they are usually IDs.
3. **Missing offsets** are assumed UTC *and the assumption is written into the report*.

Calendar validation rejects `2023-02-29`, `2024-04-31`, hour 24, and leap seconds (`:60`,
unrepresentable in UTC millis). Offsets `Z`/`±HH:MM`/`±HHMM`/`±HH` all fold to UTC.

**Distribution facts.** `NumericStats` (count, mean, population σ, p50/p95/p99) for numeric
*and* temporal columns. Mean/σ always use the full population; quantiles are exact below
100 000 values and **labelled `sampled`** above it, so an estimate is never passed off as a
measurement. Timestamps get a distribution but are explicitly **not** measures.

**Two defects caught before CI**, both by independent cross-checks rather than guesswork:
a wrong day offset in a test (68, not 67, verified against Python `datetime`) and a
floating-point tolerance comparison (`hits >= tol*total` wrongly rejects at `tol=0.07`;
now uses division, matching `column.rs`).

**Fixture hardening.** A workspace snapshot was observed re-encoding `latin1.csv` into valid
UTF-8, which would have made the fallback test vacuous. Added `.gitattributes` (binary) plus
a test asserting the fixture's *defining property* so corruption fails loudly.

New fixtures: `timestamps.csv`, `naive_timestamps.csv`, `ambiguous_dates.csv`,
`day_first_dates.csv`. Rust tests **81 → 142**.

**Verified:** run 42110923391, all 6 jobs green. The schema drift gate confirms the earlier
prediction — `DataType` is not encoded in `schemas/`, so the new type caused **no artifact
drift**. Emulator smoke still reports `ENGINE_FFI_OK` / `POC_OK` (12 rows); that remains
emulator evidence and does **not** satisfy the device rule.

Three defects were caught by the strict gates and fixed, none by guessing: a tuple nested
wrongly in `Some(...)` (compile error), `assert_eq!` against literal bools and a fixed-size
`vec!` (clippy), and a wrong p99 expectation — the implementation was right, since type-7
quantiles interpolate (`p99` of `[1,3]` is `2.98`, not the max).

## What 1.1.3 adds

**An explicit rule table.** `RULE_TABLE` (R1–R6) replaces the Phase 0 ad-hoc branches, and
every component's explanation names the rule that produced it:

| Rule | Fires when | Emits |
|---|---|---|
| R1 | always | `metric_card` (record count) |
| R2 | a numeric measure exists | `metric_card` (average) |
| R3 | temporal **and** a measure | `line_chart` |
| R4 | temporal but **no** measure | `timeline` (+ severity when present) |
| R5 | a dimension with 2–12 distinct values | `bar_chart` (avg measure, else count) |
| R6 | always | `data_table` |

R3 and R4 are mutually exclusive — the same time axis is never drawn twice. Selection is
deterministic (stable tie-breaks on confidence then name), so **field order in the file
cannot change the generated interface**; that is asserted. Average is used rather than sum
because a mean stays meaningful for rates as well as totals, and the explanation says so.
A perfectly unique integer is deprioritized as a measure, so row ids in small files are not
averaged into a headline metric.

**All five validator passes are now active.** Pass 3 (`validate_bindings`) checks every
binding against the *live profile*: fields must exist, and aggregations must be meaningful
for the physical type — no `sum`/`avg` of text or timestamps, while `min`/`max` of timestamps
is allowed. Pass 5 gained resource ceilings (`page_size ≤ 1024`, bar `limit ≤ 2000`, 1–8 line
series) and a closed aggregation vocabulary. `validate_with_profile` runs all five, and
`morphic-core` now uses it.

**11 golden snapshots** (`insta`) lock the compiled `WorkspaceDoc` for the fixture corpus
plus synthetic log/dimension-only/text-only cases. Each golden is *also* asserted to pass all
five validator passes, so a snapshot can never enshrine an invalid document. CI generated
them once on introduction and committed them; from the next run the step reports
**"snapshot gate is LIVE"** and updates are never enabled.

**A real defect the goldens exposed:** binding variant fields serialize **snake_case**
(`time_field`), because the enum's `rename_all` applies to variant *names*, not their fields.
The new validator's JSON Pointers were written `timeField` and addressed keys that did not
exist. Fixed, and a test now resolves **every** issue pointer against the serialized document
so the class of defect cannot recur. Serialization was deliberately left unchanged — renaming
it would break schema v1.0 and cascade into the drift-gated artifacts.

Rust tests **142 → 187** (including the 11 goldens).

**Verified:** run 42148213108, all 6 jobs green. The golden gate is confirmed *live*: the
"Golden snapshots present?" step succeeded and the auto-commit/bootstrap step was
**skipped**, proving the committed snapshots were compared rather than regenerated.
Emulator smoke still reports `ENGINE_FFI_OK` / `POC_OK` (12 rows) — emulator evidence only.

## What 1.1.4 adds

**The bridge became stateful — that was the real gap.** The Phase 0 bridge built a fresh
`Engine` per call and threw the parsed `Table` away, so `queryPage` and `metricData` had
nothing to query. Sessions now retain the `Table`, profile, and document; engines are cached
per storage root, so a page request executes against canonical Rust state instead of
re-parsing the file. `API_VERSION` moved **1 → 2**; the Phase 0 entry points are retained.

**Real paging and aggregation in Rust.** `morphic-query` grew a bounded pager (limit clamped
to `1..=1024`, null-safe cells, timestamps rendered as ISO-8601 UTC, case-insensitive search)
and aggregation (`count`, `distinct_count`, `sum`, `avg`, `min`, `max`) with typed errors.
An aggregation over no rows returns **null, not zero** — "no data" and "zero" are different
answers. `metricData` resolves the `metric_card` binding *in Rust*; Flutter never computes a
number it displays.

**Reopen is genuinely queryable.** `morphic-workspace` persists the imported source bytes
atomically, and `open_session` rehydrates a session from them. The deliberate trade-off is
**re-ingest on open**; the columnar `snapshot.bin` cache was reviewed in 1.1.6 and
**deferred** (see below) rather than built against an unmeasured budget.

**Dart controllers with contract tests.** `EngineController` and `ImportController` own the
view state; 17 new Dart tests assert the contract against a recording fake, including that
the controller *forwards* a page plan rather than slicing locally, that engine warnings are
surfaced rather than swallowed, and that failures become error states instead of crashes.

### Two deviations, recorded rather than hidden

1. **frb + cargokit deferred to M1.7** ([ADR-0014](../decisions/ADR-0014-bridge-transport.md)).
   The sandbox has no Rust or Flutter toolchain, so a *code generator* plus Gradle/CMake
   integration could only be validated blind through CI round trips — and it is orthogonal
   to this task's actual value. The architectural guarantee holds: only `morphic-bridge`
   knows about FFI.
2. **Dart does not yet consume the native progress callback.** The callback is real and
   contract-tested in Rust (including phase sequence and the null-callback path).
   Cross-isolate delivery (`NativeCallable.listener` + a worker isolate) lands with the
   import UI in **1.1.7**, along with moving the FFI import off the UI isolate — which is
   required before any 10 MB responsiveness claim. Until then `ImportController` reports
   honest coarse stages and does not invent sub-stages it cannot observe.

### Defects the gates caught

Five round trips, each fixing something real: `rows_read` was `usize` where the FFI struct
declared `u64`; the bridge used a `serde::Serialize` bound without depending on `serde`;
a doc line beginning `>=99%` parsed as a Markdown blockquote (clippy `doc_lazy_continuation`);
and two tests failed because **the fixtures were unrealistic** — an all-distinct integer
column is classified as an *Identifier* by the documented ≥99%-unique rule, so it earns no
measure metric. The data was corrected to repeat amounts like real sales data, and a
dedicated test now **documents the heuristic limit** instead of leaving it implicit (scored
role selection remains M1.4).

`flutter analyze` also gained the same capture → report → enforce treatment as the Rust job;
before this, an analyzer failure produced no readable output in the commit-comment channel.

**Test growth:** Rust **187 → 232**; Dart **3 → 20**.

**Verified:** run 42159894430, **all 6 jobs green**. The Android APK built the new bridge for
all 3 ABIs and passed 16 KB alignment; emulator smoke reports `ENGINE_FFI_OK` / `POC_OK`
(12 rows). That remains **emulator** evidence and does **not** satisfy the device rule.

## What 1.1.5 adds

**A closed-world registry that cannot silently drop a component.** `ComponentRegistry`
mirrors the Rust validator's vocabulary, and an unrenderable type gets a *specific* label:
`scheduled` (bar/line/timeline → M1.4), `reserved` (a validation problem), or `unknown` (a
document from a newer version). Those are three different situations and do not share one
vague message. `registry_drift_test.dart` reads `ACTIVE_COMPONENTS` / `RESERVED_COMPONENTS`
straight out of the Rust source, so adding an engine-side type without touching the runtime
**fails the build**.

**`metric_card`** shows the value Rust computed, with loading / error+retry / no-data / value
as four distinct states. **`data_table`** keeps its header outside the vertical scroll view
but inside a shared horizontal one, so the header stays pinned yet moves with the rows
sideways. Paging and debounced search are sent to Rust as a plan; the widget never slices or
filters locally. `page_size` is clamped to the engine's 1024 ceiling.

**Adaptive layout** honours `layout.order` exactly — metric cards flow into 1/2/3 columns by
width, but nothing is re-sorted. Display formatting never coerces a type and never turns
`null` into `0`.

### The runtime was unreachable — and that was the real gap

Every widget test passed while **no route actually constructed the runtime**: `/workspace`
built `WorkspaceScreen()` with no controller, so the app still showed the Phase 0 structural
outline. A runtime that exists but is never navigated to is not a delivered feature.

Both entry points are now wired: the PoC performs a **real import** (session retained) and
opens the live runtime; Home reopens into a **live queryable session** rather than a read-only
document. Ingest warnings travel with the navigation and are surfaced on the workspace.
`wired_flow_test.dart` drives Home → PoC → Generate and Home → reopen to keep it that way.

### Defects only a real Android build could expose

The emulator smoke was extended to drive *generate → page*, and it immediately failed three
times for three different real reasons — none of which any widget test could see:

1. **`uiautomator` only dumps on-screen nodes.** The pager footer was below the fold, so the
   check could not see a table that was working. Both the CI smoke and the device harness now
   scroll until the data is visible.
2. **The row fingerprint matched a metric card.** Guessing "multi-line text with digits"
   identified `Records / 600 / count · rows` as a data row, so the check passed before ever
   reaching the table. Rows now carry an explicit `Row N: a, b, c` semantic identity — correct
   for assistive tech and unambiguous for automation.
3. **Metric cards were ~164 dp tall each.** With the full rationale inline, two metrics plus
   two chart placeholders pushed the data table off a phone screen. Explanations are now
   clamped with the full text in a tooltip, and deferred components are compact and
   expandable — still labelled, no longer a wall.

One correctness fix came from writing tests rather than from CI: `EngineController.metric()`
returned `null` on failure, which the card would have rendered as **"No data"**. `null` is a
legitimate metric answer, so failures now rethrow and render as an error with a working retry.

**Test growth:** Dart **20 → 85**; Rust unchanged at 232.

**Verified:** run 42174208791, **all 6 jobs green**. The emulator reports
`RUNTIME_OK … range 1-256 of 600`, then after tapping Next page
`PAGING_OK … range 257-512 of 600` with `Row 1` → `Row 257`. That is real evidence that paging
executes in Rust inside an Android build — but it is **emulator** evidence and does **not**

`tools/device_smoke.sh` grew from 7 to **10 checks**, adding `generateWorkspace`,

## What 1.1.6 adds

**Content-addressed datasets.** Source bytes live at `datasets/<sha256>/source.csv` and a
workspace points at them through `dataSources[].datasetId`. Importing one file into two
workspaces stores **one** copy; deleting a workspace never deletes a dataset another one
references. Re-importing the same bytes after data loss relinks an existing workspace by hash,
with no manual repair step. Identity is SHA-256 (`sha2`, already approved in
[dependency-strategy §3](../engineering/dependency-strategy.md)).

**Write-ahead journal, and a kill/restore test that means something.** `save_workspace` fsyncs
a journal record *before* the atomic rename of `workspace.json`. If the process dies in
between, the next open finds a journal revision newer than the base document, promotes it,
and compacts the journal away. Recovery is **idempotent** and a **stale** entry can never roll
state backwards — both are asserted directly. The acceptance test simulates the crash by
writing only the journal record and leaving `workspace.json` at the previous revision.

**Torn writes and corruption are distinct outcomes.** A half-written trailing JSONL line is
counted and dropped, not treated as a fatal journal. An unparseable `workspace.json` is rebuilt
from the journal when possible; when it is not, the bytes are renamed to
`workspace.corrupt.json` and a typed `Corrupt` error is returned — evidence is kept, never
silently discarded. A torn `library.json` cannot hide workspaces that are still on disk.
`atomic_write` now fsyncs the **directory** as well as the file, so the rename itself is durable.

**Legacy workspaces still open.** Anything saved before 1.1.6 kept `source.csv` inside the
workspace folder and used the workspace id as `datasetId`. Those open through a fallback and
are migrated to content addressing on first open, **without bumping the revision** — a storage
migration is not a user edit.

**Degraded mode instead of a crash.** A missing or unparseable source is a typed
`SourceUnavailable`. The document and layout still load, the snapshot carries
`degraded: true` plus the engine's own `notice`, and data calls return a typed error rather
than an empty page that would read as "your file had no rows". Flutter shows the notice
verbatim in a banner; it never invents a cause.

**Recents are actually recent.** `list_workspaces` sorts by `modifiedAt` descending with an
id tiebreak, so Home's ordering is deterministic.

### Two deferrals, with reasons

- **`snapshot.bin`** (columnar reopen cache) is **not** built. Reopen re-ingests the source,
  which is correct and tested. The binary format is a performance optimization serving a
  10 MB budget that is **still unmeasured on real hardware**; committing to a versioned binary
  format before that data exists would be speculative risk. It returns with the perf work.
- **`.lock` files** are **not** written. The app is single-process and the engine already
  serializes session access with a mutex, so a stale-lock protocol would add failure modes
  without a concurrent writer to protect against.

Both are recorded in the crate documentation so the gap is visible at the code, not only here.

## Exit criteria — not yet met

M1.1 exits only when AT-01/AT-02/AT-09(partial) pass **on a physical mid-range device** with
committed evidence, and the 10 MB → workspace ≤ 3 s budget is measured there. Tasks
1.1.1–1.1.5 are done and CI-verified, 1.1.6 is implemented and awaiting CI verification, and
1.1.7 remains open. **No gate-valid device evidence has been committed**, so **no M1.1 exit
claim is made**. A manual C51 pass on 2026-11-06 matched every expected value and the tester
attests to completing the force-stop/reopen and airplane-mode steps, but it produced no adb
log, no `evidence.json`, and no timings — see
[the report](../engineering/manual-test-reports/2026-11-06-realme-c51.md). The 10 MB → workspace ≤ 3 s budget is
still **unmeasured**: the bundled sample is 30 KB, and there is no file picker yet.

**Hardware available for the device pass:** realme C51 (RMX3830, Unisoc T612, 4 GB, eMMC 5.1)
and Galaxy A15 (Helio G99 / Dimensity 6100+). Both are **low** class under §2 of the device
matrix, whose milestone-exit minimum is **mid (Pixel 6a/7a class)**. Runs on these two produce
useful low-end evidence but **cannot close M1.1**; a mid-class device is still required. See
[device-test-script.md](../engineering/device-test-script.md).
