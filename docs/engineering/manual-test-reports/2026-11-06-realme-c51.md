## Defect found — timestamps were unreadable

Visible in `…110227.png`, `…110359.png`, `…110403.png`: the `time` column renders
`2026-11-05T1…` for every row.

**Cause:** columns were sized from the *header* only. `time` is 4 characters, so the column
was clamped to the 96 dp minimum (~11 characters), while an ISO-8601 UTC value is 24
characters. Horizontal scrolling cannot reveal it, because the ellipsis is applied *inside*
the fixed-width column. For a log workspace the time axis is the primary field, so this made
the main column unusable.

**Fix:** columns are now measured from the widest visible cell value (header included),
frozen after the first page so they do not jitter while paging, and capped at 300 dp. A
24-character timestamp now gets ~197 dp. Tapping any cell opens the full value as selectable
text, so a capped long value is still readable. Six regression tests cover it, including the
exact timestamp case and the no-jitter property.

**Verified:** CI run [42183434847](https://github.com/mkl745/Morphic/actions/runs/42183434847),
commit `5dbdf61`, all 6 jobs green, **91 Dart tests**. The emulator still reports
`RUNTIME_OK … 1-256 of 600` and `PAGING_OK … 257-512 of 600`, so the new per-cell tap targets
did not break row semantics. The fix needs a confirming look on the C51 — the timestamps
should now be fully readable without scrolling.

## Observation, not yet a defect

`message` is inferred as a **dimension** (`…110100.png`). With ~17 distinct messages over 600
rows it satisfies the low-cardinality rule. It did not affect this workspace — `service` won
the dimension slot deterministically — but free-text message columns will often be better
treated as text. Scored role selection is M1.4.
