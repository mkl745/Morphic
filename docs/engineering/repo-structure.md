created; every folder has a Phase 0/1 consumer.

## Notes on tricky bits

- **Why the bridge crate lives in the app:** cargokit expects the Rust crate inside the
  Flutter package (`rust/` + `rust_builder/`). It is still a *workspace member*, so engine
  crates are path deps with one lockfile and one `target/`.
- **Generated code is committed** (`lib/bridge/`, `rust/src/frb_generated.rs`,
  `rust_builder/`, `schemas/*.json`) and CI regenerates + diffs. Reviewable, hermetic,
  offline-buildable.
- **`fixtures/` is versioned test data**, not user data: every file has a manifest
  (`fixtures/manifest.json`) with origin, license, and expected profile/plan outcomes.
  Large perf fixtures (>5 MB) are generated by `tools/gen_fixtures.py` at bench time, not
  committed.
- **No `graphics/`, no `integrations/`, no `tests/` top-level** yet: graphics backends are
  benchmark-gated (ADR-0008); platform adapters live in the app until iOS needs extraction;
  tests live next to their crates/package (Cargo/Flutter convention). Cross-cutting E2E
  specs live in `docs/roadmap/mvp-acceptance-tests.md` and are implemented as
  `integration_test/` cases.
- **iOS folders** are created by `flutter create --platforms=android,ios` but iOS is not
  built/released until Phase 4; keeping the folder costs nothing and preserves parity.
